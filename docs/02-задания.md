## Задание 4. Декомпозиция замка + честный отказ

Вариант А — замок по лоту/шарду с `tryLock(timeout)`:

```java
private ReentrantLock lockFor(String lotId) { /* hash(lotId) % shards */ }

@Override
public Call buy(String lotId, BuyRequest request) {
    return guardedTx(lockFor(lotId), props.lockTimeoutMs(),
            () -> Transactions.buy(book, lotId, request.buyerId(), request.qty(), request.expectedVersion()));
}
```

Вариант Б (после обсуждения в тройке) — `ReadWriteLock`: почему витрина должна
улучшиться, а покупка — нет.

Замеры, которые надо снять и сравнить:

```bat
java -jar ...harness... --only=sync,твоя --ops=60
java -jar ...harness... --only=sync,rw,твоя --read-share=0.9 --threads=32
mvn -pl exchange-server -am test -Dtest=ReadWriteMicroBenchmarkTest   :: честный замер без HTTP
```

**Ловушка, в которую вы обязательно попадёте, и это хорошо.** `tryLock` возвращает
`503 BUSY`, и если клиент не умеет повторять — вы «починили» сервис так, что заказы
стали теряться. Проверь оба режима клиента:

```bat
java -jar buyer-client/target/buyer-client-1.0.0.jar --retries=1
java -jar buyer-client/target/buyer-client-1.0.0.jar --retries=8 --backoff=5
```

В отчёт: число `busy`, сколько из них превратилось в успешные покупки после включения
повторов, и что бы вы выбрали в проде — ждать в `lock()` или отказывать и повторять.

В отчёте — ровно эта таблица: «до / после» по колонке `инварианты` + объяснение, почему

## Задание 6. Оптимистичная блокировка: два места, а не одно

## Задание 9. Взаимоблокировка: увидеть и убрать

```bat
curl -X POST "http://localhost:8080/api/lab/strategy?name=deadlock"
java -jar buyer-client/target/buyer-client-1.0.0.jar --ops=200
java -jar seller-client/target/seller-client-1.0.0.jar --ops=60
curl http://localhost:8080/api/lab/threads
```

Через несколько секунд `GET /api/lab/threads` покажет `"deadlocked": true` со стеками —
это `ThreadMXBean.findDeadlockedThreads()`. Обратить внимание студентов: **в логах при
этом пусто**. Ни ошибки, ни исключения, ни «ура, deadlock».

Потом — двумя шагами:

1. включить спасение: `exchange.deadlock-escape=true` (или `curl -X POST .../lab/strategy?name=trylock`),
   убедиться, что сервис снова живёт, и назвать цену (`busy`, повторы);
2. убрать саму возможность цикла: единый порядок захвата (см. `TwoLevelLockEngine`).

В отчёт — скрин тред-дампа и перечисление четырёх условий Коффмана с указанием, какое
из них вы разорвали своим решением.
